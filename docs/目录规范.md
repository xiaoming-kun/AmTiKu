# 目录规范

> 一句话：**根目录只放"入口"和"数据区"，任何"一次性的东西"都不许留在根目录。**
>
> 这份文档解决的是"东西越堆越乱"：每个目录只回答三个问题——它是什么、谁在写它、删了会怎样。

## 一、先分清三类东西

| 类别 | 判断标准 | 例子 | 处理方式 |
|---|---|---|---|
| **真相** | 丢了就真没了，重建不出来 | `题目/*.tex`、`图片/`、`知识点.json`、`回收站/` | 只经由对应模块写；不进 git（私有数据）；改前有备份/快照 |
| **生成物** | 删了能重跑出来 | `数据/索引.sqlite`、`数据/缓存/`、`web/dist/`、`题目/备份/`、`*.tmp` | 随便删；越少越好 |
| **一次性产物** | 为某一次任务产生，事后只用来查 | 缺图清单 PDF、体检报告、评价批次、导出中间件 | 用完挪进 `归档/` 或 `记录/` |

**根目录只允许出现第一类 + 入口文件。** 第二、三类出现在根目录，就是没归位的信号。

## 二、顶层目录职责表

| 目录 / 文件 | 是什么 | 谁写 | 删了会怎样 | 整理时能动吗 |
|---|---|---|---|---|
| `题目/` | **题库唯一真相**，`001.tex`…`007.tex` 分卷（每卷 ≤5000 题） | `amti/store.py` | 题库没了 | ⚠️ 只能经 `store.py` 改；`*.tmp.*` 是写库残留，可清 |
| `题目/备份/` | 每次整库重写前的上一代（只留最近 3 代） | `store.py` | 丢一次回滚能力 | 可删；**空的/残缺的目录要删掉**，它会占轮转名额 |
| `图片/` | 内容寻址命名的配图（`<hash>.png`） | `amti/images.py` | 题目配图全断 | ❌ 不许改名、不许移动 |
| `知识点.json` | 152 个考点的五要素 + 星级 | 手工/`amti/pointbook.py` | 考点体系没了 | 根目录必须留，`amti/knowledge.py` 按固定路径读 |
| `归档快照.json` | 存量题基线，`diff`/`accept` 靠它判"有没有被偷改" | `amti.py snapshot` | 下次验收没有对比基准 | 根目录必须留 |
| `数据/` | 运行时数据：`索引.sqlite`、`缓存/`、`录题/` 流水线产物、`订正台账` | 各模块 | 索引/缓存可重建；`录题/` 是模型跑过的成品，别乱删 | 见下 |
| `数据/索引.sqlite` | 全文搜索索引 | `amti/fts.py` | 下次搜索自动重建 | 可删 |
| `数据/缓存/` | 透明化等图像处理缓存 | Web 服务 | 下次请求重算 | 可删 |
| `数据/录题/` | 录题流水线的扫描页、结构化产物、成品 | `amti/ingest.py` 等 | 扫描页可重渲染；`成品.json` 重跑要花模型时间 | 别整体删 |
| `试卷/` | 组卷存档 `存档.json` + `标准化录入/` 素材 | Web 服务 / 录题 | 已存卷子没了 | 别动；`*.tmp` 和 `*.aux/.log/.out` 可清 |
| `变更记录/` | **迁移留痕**：每次改存量数据写一份 `.md` | `amti/audit.py`、`fixups.py` | 改题依据没了 | ❌ 界面按 `*.md` 平铺读，**不能分目录** |
| `回收站/` | 删掉的题（可恢复） | `amti/trash.py` | 删题不可恢复 | 别清 |
| `待解/` | 待补答案/解析的题 | `amti/exchange.py` | 待办队列没了 | 别整体删 |
| `待录入图片/` | 录题暂存区（丢图进来再录） | 人工 / `amti/vlm.py` | 只是暂存 | 录完可清空 |
| `记录/` | **人工工作记录**：体检、审阅、清理报告 | 人工 | 历史排查线索没了 | 按需归档 |
| `题库评价/` | 全库评价与复核材料（**含真题、真实校名，不进 git**） | 评价脚本 | 评价结论没了 | 别进 git，别乱动 |
| `设计/` | 内部设计/规范/交接文档（含真题字样，不进 git） | 人工 | 设计依据没了 | 只增不改 |
| `脚本/` | 批量/一次性脚本（`ROOT = parents[1]`） | 人工 | 历史工具没了 | 一次性脚本用完可挪 `归档/` |
| `归档/` | **一次性产物的家**：`一次性产物/<日期>_<名字>/`、未引用图片快照、清理清单 | 人工 | 留档没了 | 这里的唯一职责就是"别占根目录" |
| `测试/`、`docs/`、`packaging/`、`web/`、`amti/`、`demo数据/` | 代码与文档 | 开发 | 程序跑不起来 | 见 `AGENTS.md` |
| `AmTiKu`、`启动.sh`、`amti.py` | 入口 | 开发 | 启动不了 | 根目录必须留 |

## 三、新东西该放哪（决策表）

| 你要放的东西 | 放这里 |
|---|---|
| 新的批量脚本 | `脚本/`（路径用 `Path(__file__).resolve().parents[1]`） |
| 一次性导出的 PDF / TeX / 编译中间件 | `归档/一次性产物/<日期>_<名字>/` |
| 一次体检、一次审阅的报告 | `记录/` |
| 全库评价的一批结果 | `题库评价/<批次名>_<日期>/` |
| 录题素材（扫描页、图、中间 JSON） | `数据/录题/<卷名>/` |
| 要写进题库的数据 | **不直接写 `.tex`**：走 `amti/normalize.py`（成片规则）/ `fixups.py`（逐题订正）/ `store.py` |
| 临时文件 | 别落盘；必须落盘的写到 `数据/缓存/` 或 `/tmp` |

## 四、四条铁律

1. **题库的唯一真相是 `题目/*.tex`**，任何批量改动都走 `store.py` 的写接口，别手改。
2. **`图片/` 下的文件名是内容哈希**，改名 = 断引用，永远不要动。
3. **不用 `.bak` 备份**，用 `git commit`；数据由 `snapshot` + `题目/备份/` 负责。
4. **根目录不放导出物、编译中间件、临时文件、脚本**——这三类是"乱"的全部来源。

## 五、定期清理

```bash
# 写库残留的临时文件（进程被杀就会留下，单个 14MB，实测堆到过 4.2GB）
find 题目 -maxdepth 1 -name '*.tex.tmp.*' -print -delete

# 空的/残缺的备份目录（会占用"只留 3 代"的名额，把真备份挤掉）
ls -la 题目/备份/

# LaTeX 编译中间件
find 试卷 归档 -maxdepth 2 \( -name '*.aux' -o -name '*.log' -o -name '*.out' -o -name '*.synctex.gz' \) -delete

# Python / 编辑器垃圾
find . -name '__pycache__' -prune -exec rm -rf {} + ; find . -name '.DS_Store' -delete
```

清理前先 `python3 amti.py verify`（结构合法）与 `python3 amti.py diff`（存量有没有被改），
清完再跑一遍。**清理只删生成物，动到"真相"就停手。**
