### 题目长什么样

一道题就是一个 `question` 环境，前面一行元数据（JSON）：

```latex
%% @q {"key": "高考真题汇编/2024/新高考I卷#1", "type": "single_choice", ...}
\begin{question}
已知 $A=\{x\mid -\sqrt[3]{5}<x<\sqrt[3]{5}\}$，$B=\{-3,-1,0,2,3\}$，则 $A\cap B=$\paren[A]
\begin{choices}
  \item $\{-1,0\}$
\end{choices}
\begin{solution}
因为 $1<\sqrt[3]{5}<2$ …… 故选 A。
\end{solution}
\end{question}
```

- **答案写在作答位置**：选择 `\paren[A]`、填空 `\fillin[$-1$]`
- **正文是字段的真相**，元数据行只补 LaTeX 表达不了的（key / 来源 / 考点）
- 所以**直接改正文是有效的**

## 三、日常怎么用

### 找题

- **左栏是考点树**：点**大类名**＝看这一章，点**小类名**＝看这一节，再点一次取消
- 筛选条：排序 · 类别 · 题型 · 难度 · 年份 · **有/缺**
- 默认排序 **易 → 难**
- 详情页的考点标签可点，一下跳到同类题
- 列表上的红标签是**缺什么**（缺答/缺析/缺图）—— 不显示＝齐全

### 删题（危险操作，所以最严）

详情页「删除这道题…」或列表「删除选中 N」→ 弹窗选原因（`现在的高考不考了` / `无`）
→ 填口令 → 确认。

- 删掉的题**进回收站，存的是整道题**，随时能原样恢复
- 口令 `0808`（改：`export AMTIKU_DELETE_PASSWORD=xxxx`）
- **批量删除整批原子**：有一条对不上就整批不执行
- 已删：**218 道算法框图**（算法初步已退出新课标）

### 改标签 / 补答案 / 补解析

都在详情页：

| 操作 | 说明 |
|---|---|
| 改考点、难度 | 直接点 |
| **改题型** | 点题型徽章。**题型和答案要一起改**（单选恰好 1 字母、多选至少 2 个） |
| **补答案** | 大小写、全角、顿号自动规整；单选给两个字母会被拒 |
| **录解析** | 可直接粘**整份 `.tex`**，自动取出 `solution` 那一段、丢掉导言区和题面 |

**题干和选项改不了** —— 那是题目的本体，要改得走重新录入。

### 组卷导出 · 四种卷型

| 卷型 | 组织 | 答案 | 用途 |
|---|---|---|---|
| **高考卷** | 按题型，填高考卷面结构（8+3+3+5） | 卷末 / 题上 / 不印 | 仿真模考 |
| **纯测试题** | 按题型，带考点小字与每题难度 | 卷末 | 校内练习 |
| **考点覆盖卷** | 按考点覆盖率抽题，用最少的题铺满考点 | 卷末 | 查漏补缺 |
| **讲义** | **一题一页 · A4 横版**（elegantnote 模板） | **不印** | **iPad 上用笔讲课** |

讲义模式的细节：

- 版式用 **`elegantnote`**（专为电子阅读设计的文档类），观感比 exam-zh 舒服
- **A4 横版**（297×210mm），iPad 横屏正好满屏
- **一题一页**，`\newpage` 分页，讲完直接翻下一页
- 题目下方 `\vfill` 撑满 → **整片留白给笔写**
- 字号可调：**小四 12pt（默认）** / 四号 14 / 三号 16 / 二号 22
- 不分节、无卷头、无注意事项 —— 直接进题

另外这些排版细节都做过了：

- 选项列数**按内容自适应**（短的四列、中等两列、整句话一列）
- 解答题留白**按难度**（简单 3cm / 中档 5cm / 难题 8cm）
- 题目和它的留白用 `\filbreak` **绑成一块**，不会被分页拆开
- 题干和选项用 `\needspace` 保护，**不会出现"选项跑到下一页"**
- **不印出处**（模拟题的出处是原书页码，没有意义）

### 画布讲义 · 自由排版（Slidev）

上面那张表的「讲义」是**老的 elegantnote 一题一页**。现在多了一条路：
题库顶栏「**制作讲义**」→ **画布上自由拖拽排版** → 生成 PDF。

- 题目/标题/知识点/正文/公式/表格/表情/留白都是可拖的块，位置和大小随意
- 右栏调字号、行距、页面比例（16:9 / A4 / 4:3）、标题与正文字体
- 开关：**显示答案**、**高考题标出处**（默认开，题目前加「（2024新高考I卷 第1题）」）
- 多页、可保存再编辑、生成时有进度浮层（阶段 + 计时）
- 配图（含**选项里的图**）自动嵌进 PDF

细节与实现见 **`设计/讲义系统.md`**（含「预览与导出必须一致」的规矩和踩过的坑）。

## 四、外部 AI 怎么接进来

题库**不调用任何模型端点**，只做"出题"和"收题"两头。两条链路：

### 链路 A：白纸求解（把没做的题给人做）

```bash
python3 amti.py export-unsolved --split 100 --outdir 待解/中档题 --difficulty 中档题
# 把某一批贴给任意 AI（提示词见 待解/求解提示词.md）
python3 amti.py collect 待解/中档题/第01批_….md          # 干跑，看报告
python3 amti.py collect 待解/中档题/第01批_….md --yes    # 确认后落盘
```

文档开头带**给模型看的填写说明**，回收时**靠 `题号：` 那一行对上号**，不靠顺序 ——
模型漏做、跳做、重排都不影响。

**两条硬规矩**（写死在 `exchange.collect` 里，不是提醒）：

- **客观题的答案栏必须填** —— 只写解析不填答案的**直接退回**（那等于这题还没做）
- **解答题的答案一律写「见解析」**

### 链路 B：识图录入（把一整份试卷整理成题）

提示词在 **`设计/识图录入提示词.md`**，整段复制给带视觉能力的模型 + 试卷文件。
模型交付 `题目.tex` + `图片/` + `录入报告.md`，然后：

```bash
python3 amti.py ingest --file 我的输出/题目.tex --src 我的输出/图片 \
    --book 模拟题 --label 第14套武汉三调 --region 武汉 --year 2026
```

录入管线**自动**做：图片改名入库 → 规范化 → 13 项审查（不合格拦下并说明原因）→
查重 → 干跑 → `--yes` 落盘。

> 提示词里禁止的每一种写法都有程序兜底。实测：正面例子 0 违规通过，
> 反面例子（`\(…\)`、`%` 注释、残留空括号、空位嵌在数学模式里、`\left[` 不配平）
> **5 处全被拦下并自动修正**。

### 链路 C：录题台（本地大模型全自动，2026-09-16 新增）

链路 B 要**人工把提示词贴给外部模型**；链路 C 把这套流程做成了本机的一键工具：

```bash
python3 -m amti.web.record_server --port 8901     # 打开 http://127.0.0.1:8901
```

把试卷 PDF **拖进去** → 后台用本地 VLM（LM Studio `qwen3.8-27b`）逐页识别 →
在界面上核对 → 「确认入库」。命令行同一套逻辑：

```bash
python3 -m amti.record --pdf 试卷.pdf --answers 答案.pdf --book 模拟题 --out 题目.tex
python3 -m amti.record --dir ~/Desktop/27年试卷/试卷 --outdir 数据/录题/输出   # 批量
```

**三条规矩写死在 `amti/record.py` 里**（不是提示词里的提醒）：

| 规矩 | 实现 |
|---|---|
| **带图题一律不录** | `split_figures()`：`figure=有` 的题整题丢掉 |
| 8/11/14/18/19 的带图题**登记原卷位置** | 同上，进 `register`：卷名 + 第几页 + 图上中下 + 图的描述 |
| 没解析写「解析无」 | `to_tex()`：`solution` 为空就写 `NO_SOLUTION` |
| 题目↔答案↔解析一一对应 | `merge()`：答案页**只取 ANS/SOL/KEY，不碰题干**（答案卷常把题干缩写重排） |
| 出处 + 原卷题号 | `%% @q` 的 `meta.source_label` / `meta.source_no`，如「2026新课标I卷 第5题」 |

**答案与解析不在一个文件里**也吃：同目录下的答案卷按文件名自动配对
（阈值 0.80 是拿 15 份真实卷名量出来的），界面上一眼能看见、能改。

> 识别出来的中间结果**一页一个 json** 落在 `数据/录题/<卷名>/scan/`，
> 所以中断了重跑只补没做完的页，不会从头再来。

## 五、数据是怎么保住的

题目量大、改动频繁，**"改坏"比"没做完"可怕得多**。每一层都有拦截：

### 1. 写盘三层安全网（`store.rewrite_all`）

| 层 | 做什么 |
|---|---|
| ① 写前自检 | 先写 `.tmp`，**重新解析一遍核对 key 集合** —— 对不上就根本不碰正式文件 |
| ② 自动备份 | 改名前把上一代卷文件整份留到 `题目/备份/`（留 3 代） |
| ③ 写后复验 | 改完从磁盘再读一遍，不对就**自动回滚** |

外加**跨进程写锁**（`fcntl.flock`）+ **唯一临时文件名**（带进程号）。

### 2. 往返一致性（`store.roundtrip_problems`）

**题目写出去再读回来，内容指纹必须一个字节都不变。**

这是在防一类很隐蔽的 bug：`store.render_question` **同时是写库函数**，
一旦往渲染里塞了"出卷子时才该做的事"，每写一次库就悄悄改一次数据。

> 实测踩过：给渲染函数加了「TikZ → 预渲染图片」的替换，
> 一次批量迁移就把 **236 道题的题干**改写成了 `\includegraphics`，
> 还把 TikZ 源码弄丢了。**已从旧项目按题干相似度全部恢复（117/118 置信度 ≥0.85）。**

### 3. 基线监控（`diff`）

顶栏一个状态点，点开看明细。**只有第一类是报警**：

| 显示 | 含义 |
|---|---|
| ⚠ **内容变化 N** | **没登记过的改动 —— 这才要看** |
| 界面补录 N | 界面上改了答案/解析/题型 |
| 规则迁移 N | 批量规范化改的（**有 `变更记录/` 为证**） |
| 求解写入 N | 求解器写的 |
| 录入升级 N | 点「用这份更新」升级的 |
| 回收站 N | 人工删的，可恢复 |

有意改完数据后点「**更新基线**」，这些就成了"已确认"。

### 4. 删题可恢复（回收站）

「删除」不是真删。存的是**整道题**（题干/选项/答案/解析/配图/tikz 源码），
恢复是原样放回。

`测试/删题安全自检.py` 专门证这件事：口令不对不动、题号不存在整批不执行、
**只少那一道而其余逐字节不变**、恢复后**全库指纹回到删除前**。

### 5. 规范是唯一入口

**全库唯一把题目改成规范形态的地方**是 `amti/normalize.py`，
**唯一判定合不合规的地方**是 `amti/conform.py`。
录入、求解、界面补录、批量迁移 —— 四条路走同一套。

`conform` 每个检查项都配**正反控制样本**（坏样本必须抓到、干净样本必须放过），
**先证明检查器本身管用**，再拿它去查数据。

### 6. 图形与编译不拖后腿

- **TikZ 预渲染**：库里的 TikZ 图在录入时渲一次存成矢量 PDF，
  卷子里只 `\includegraphics`。图和原来一模一样（还是 LaTeX 画的、还是矢量），
  但**卷子编译不再依赖 pgfplots / 自定义样式**
- **编译体检**：`amti.py compilecheck` 批量编译 + 二分定位，
  把"抽到那道题才炸"的错误提前查出来
- **导言区只有一份**（`paper._preamble`）—— 四种卷型共用

### 7. 验收四层（`python3 amti.py accept`）

```
单元自检 → 规范审查 → 端到端渲染（KaTeX + LaTeX + 图片） → 快照
```

外加 `solve` / `fixups` / `trash` / **删题安全自检** 各自的专项自检。

## 七、几个要知道的事实

### 依赖都在项目里

Python 依赖（`fastapi` / `uvicorn` / `pydantic` / `pillow` / `numpy` / `PyMuPDF`）
装在**项目内的 `.venv/`**，不用系统或用户级的 site-packages ——
换台机器、或者系统 Python 升级了，这个项目照样能跑。

```
.venv/                项目自带 Python（133 MB）
requirements.txt      钉死的版本
web/node_modules/     前端依赖（也在项目里）
```

启动脚本会自动优先用 `.venv/bin/python`；`.venv` 不在才退回 `python3`。

重装：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-user -r requirements.txt
```

> ⚠️ 本机设了 `PIP_USER`，直接 `pip install` 会报
> `Can not perform a '--user' install`。加 `--no-user` 就行。

**搬不走的两样**（只能装在系统里）：

| | 为什么 |
|---|---|
| TeX Live | 好几 GB，且 `xelatex` 必须能被 PATH 找到 |
| LM Studio | 本地模型服务，是个独立 App |

### 服务会自动退出

「关掉页面 25 秒后退出」是**设计行为**，不是故障。重新进不去时：

```bash
AmTiKu 启动
```

## 八、版本管理（git）

仓库是**纯本地**的（没有远端），代码 + 题库 + 配图都在里面。

```bash
git log --oneline                 # 做过什么（当前 18 个提交）
git show v1.1 --stat              # 某个版本改了哪些文件
git tag -n1                       # 稳定点标签
git status                        # 当前有没有没提交的改动
git checkout -- web/src/App.tsx   # 改坏了，回滚**单个文件**
git checkout v1.0 -- web/src      # 回滚整个目录到 v1.0 的样子
```

| 标签 | 含义 |
|---|---|
| `v1.0` | 画布讲义系统上线 + 前后端结构重构完成 + 引入 git |
| `v1.1` | 讲义完善（进度动画 / 高考题出处 / 选项图 / 稳定性 / 测试 / 清理） |

**改了东西就提交**，别攒着：

```bash
git add -A && git commit -m "说明改了什么"
```

### 想要异地备份（推荐偶尔做一次）

git 历史可以打包成**一个文件**，拷到网盘/移动硬盘即可：

```bash
git bundle create ~/Desktop/AmTiKu-v1.1.bundle --all     # 约 190MB，含全部历史
# 恢复：git clone ~/Desktop/AmTiKu-v1.1.bundle AmTiKu
```

> 注意分工：**git 管"代码和文件能不能回滚"**；
> 题库内容的正式基线仍走 `python3 amti.py snapshot` + `归档快照.json`
> （`amti.py diff` 靠它判断"存量有没有被改动"）。

## 八、几条硬规矩（改代码前先读）

1. **题目有问题就改题目，不要改程序。** 数据的事在数据上解决。
2. **真要改程序就慎重改** —— 改之前先问"这条规则会不会动到存量"。
3. **验证 → 修改 → 录入**，顺序不许颠倒，也不许跳过。
4. **批量改存量必须走 MIGRATE**：`amti.py audit --rule '规则名'`（干跑）
   → `--yes`（执行）→ 自动写 `变更记录/`。
5. **不留静默修改。** 改了什么、改了几道、依据是什么，都要能事后查。
6. **检查器先自证。** 新加一条检查，必须同时给坏样本和干净样本。
7. **⚠️ 不要抄第二份。** 同一个东西有两份实现，改了这份忘了那份，早晚出事。
   已经栽过两次：导言区抄两份 → 讲义编译全死；渲染路径塞了写库不该做的事 → 污染 236 道题。

细节见 `设计/新项目顶层设计.md`、`设计/题目规范.md`、`设计/经验教训复盘.md`。
